# 交接檔：實時檢測管線 + ROI（2026-08-25）

> **一句話**：產線實時那條（觸發 → 送父端 → 判定 → 吹氣）**整套做完了、80 項驗證全過**，
> 但**從沒對真的相機跑過** —— 現場第一次上機請照 §1 的三步驟看，三分鐘就知道通不通。

## 1. ⚠ 現場第一次上機：先看這三樣（照順序）

### ① IO 觸發線 —— **最可能出事的一條**

開「面板 → 模號穴號實時檢測（觸發式）」→ 按開始 → 看狀態列那顆：

| 看到什麼 | 意思 | 怎麼辦 |
|---|---|---|
| **綠底**「IO 觸發線 Line0 就緒」 | 好，按現場開關就會觸發 | 往下走 ② |
| **紅底**「讀不到相機 IO 觸發線」 | **按開關不會有任何反應** | 改 `Devices:Camera:TriggerLine` 的線號（預設 `Line0`） |

> **為什麼特別提**：現場的觸發開關是**接在 IDS 相機的數位輸入上**，不是接 PLC。
> 這段程式是照已驗證的 `模號檢驗/相機版` 邏輯寫的，但 AIVision 的 SDK 包法不同
> （`TryFindNodeEnumeration` vs `FindNode<>`），**從沒對真的相機跑過**。
> 通不通就看那顆是綠是紅，不必翻 log。

沒有 IO 也能先驗流程 —— 畫面上有「**手動觸發**」按鈕。

### ② ROI 黃框有沒有對準

即時畫面上的**黃框就是送去辨識的範圍**。工件必須**完整落在框內**才會被採用。

**主頁與實時檢測頁的預覽下方都有「ROI 判定區」那一組**（四個功能集中在一起）：

| 按什麼 | 會怎樣 |
|---|---|
| **自訂 ROI 範圍** | 在畫面上拖一個 → 放開**即存檔生效**（免重啟）；Esc 取消；太小（<50×50）自動放棄 |
| **恢復預設範圍** | 回到出廠校正值 290,0,730×610 |
| ☑ **顯示 ROI 框** | 只是畫不畫，**判定範圍不變** |
| ☑ **顯示矩形參數** | 四角／尺寸／影像／比例，純顯示不影響作動 |

- 下面那行「目前 ROI …」永遠是**實際生效**的值，關掉框也查得到
- ROI 存的是**影像比例**（`configs/roi.json`），換相機或改解析度都不會跑掉
- 兩個畫面共用同一份：一邊改，另一邊的框立刻跟著改，管線也同步換

### ③ 父端預算：**100ms 太小**

實測（單站、本機迴路、暖機後、真實影像，各 8 片）：

| `ServerBudgetMs` | 走中央 | 父端自報耗時 |
|---|---|---|
| **100**（原拍板值） | **2~4 / 8　25~50%** | 90–107 ms |
| 150 | 4~5 / 8　50~63% | 92–115 ms |
| **200** | **8 / 8　100%** | 90–190 ms |

**照 100ms 跑，一半以上的片子會落到本機那顆較舊的雙 head。**
建議 `RealtimeInspection:ServerBudgetMs` 設 **200**；畫面上就有「中央 / 本機」比例可以邊跑邊看。
⚠ 這是**單站本機迴路**的數字 —— 跨機加網路、多站搶 GPU 都會更慢，現場要重測。

## 2. 這次抓到的六個缺口（都已補，但要知道為什麼）

我一開始只列了三項「還沒做」——**那是沒有系統性掃過**。逐條查完又找到六個會在現場咬人的：

| | 缺口 | 現場後果 |
|---|---|---|
| ① | 前處理參數**沒吃設定檔**（用預設值，`RoiW=0` 等於不裁 ROI） | 拿整幅影像找圓 → 抓到背景的圓、裁錯區域，**讀值全錯而畫面一切正常** |
| ② | 實時檢測畫面**沒有任何影像**（`<Image>` 數量 = 0） | 看不到相機有沒有動、工件有沒有進框 |
| ③ | **pieceId/trigTick 沒送父端**，還把 pieceId 塞進 `rawPath`；原圖又是最後才存 | 父端「站端原圖位置」顯示 pieceId，**溯源整條斷掉**，兩邊 log 對不起來 |
| ④ | **IO 觸發完全沒接**（相機版讀 IDS 的 `Line0`，AIVision 一行都沒有） | **現場按開關完全沒反應**，等於沒有觸發源 |
| ⑤ | 工單預期值要**人工 key** | key 錯＝整批誤判／誤吹，與工單不同步時看不出來 |
| ⑥ | 假相機沒擋 | 畫面說在跑但永遠沒有幀 → 每次觸發都變「擷取失誤」，會去查錯方向 |

另外 ROI 那塊我原本只做了「把框畫進點陣圖」，那是相機版功能的一小塊**而且做法本身也錯**
（1280×1024 的 PNG 編碼一次 10~30ms、每顯示一幀付一次；畫進圖裡也做不了拖曳框選）。
現已改成 Canvas 疊層 + 比例儲存 + 拖曳框選 + 重設 + 存檔即生效。

**教訓**：「還沒做的事」不能憑印象列，要逐條掃過每一個介面接點。

## 3. 做出來的東西（都在站端 App）

**入口：面板 →「模號穴號實時檢測（觸發式）」**（工程師以上）

```
相機每一幀 → 環形緩衝（2500ms）
IO 觸發    → 只記 trigTick + 800ms 截止，不拍照
檢測迴圈   → 窗內逐幀回頭找：快速閘門（只 Hough）→ 完整鏡片在 ROI 內？
               命中 → 前處理 → 原圖先落地 → 送父端（預算 ms）→ 逾時改本機
                    → **站端拿工單判定** → 存三件套 → 混料/NG 吹氣
               窗到期沒命中 → 擷取失誤（不吹、不存，多半是重複觸發）
```

- **判定權在站端**（工單只有站端知道；父端只回「讀到什麼」）
- **五個數字要能相加**：`觸發 = 中央 + 本機 + 擷取失誤 + 停止時中斷 + 待補`（不平畫面轉紅字）
- **三件套**：`records\yyyyMMdd\{pieceId}_raw.jpg` / `_strip.png` / `.json`
- 事件 log：`logs\realtime_events_YYYYMMDD.jsonl`

新增檔案見設計文件的「實作紀錄」。

## 7. 工作紀律（這兩天用血換的，別忘）

- **「還沒做的事」不能憑印象列** —— 要逐條掃過每個介面接點。這次憑印象列三項，實際有九項。
- **不能只驗好的那條路** —— 吹氣那次特地把舊 JSON 也送一次，才證明得了「原本真的不會吹」。
- **一件事不可以連坐後面一整批** —— 今天修掉三個同類的：
  Route A 的 415 冷卻、實時管線的預算逾時冷卻、單次瞬斷就冷卻。
- **取消請求可能會弄壞對方** —— 父端 sidecar 是 stdin/stdout 一問一答，砍掉請求會讓協定失步、污染後面 15 筆。
  正解是「只停止等待，不中止對方」。
- **設定有兩個地方 = 遲早出事** —— ROI 一律以 `configs/roi.json` 為準，appsettings 只當第一次的種子。
- **自己的測試也會說謊** —— 這兩天共四次：過嚴的閘門、快取讓 20ms 也擠得進、`\u` 判斷、
  測試執行緒沒有訊息迴圈（`BeginInvoke` 沒人跑，看起來像「畫面沒更新」）。紅燈先問「程式錯還是量法錯」。
- **功能不要散** —— ROI 一度散成三份（主頁唯讀框＋自己一份座標換算、檢測頁三顆按鈕、矩形參數沒人做）。
  同一件事就包成一組控制項，每個畫面兩行 XAML。
- 連線判斷一律 `Test-NetConnection -Port`，不要用 ping。
- 動 `.ai` 要同步 `status.json` ＋ 跑 `python D:\專案管理\process\build_dashboard.py`。
