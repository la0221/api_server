# 進度卡更新指令

> **用途**：把這份檔案複製到每個專案的 `.ai/` 底下（例如 `.ai/AGENT_進度更新指令.md`）。
> Agent 每次更新 `.ai`（寫完當天 `01_daily_log.md`）後，**照本檔步驟更新 `.ai/status.json`**，
> 讓 `D:\專案管理` 的儀表板能掃到最新進度。
> **這是給 agent 讀的指令，不是給人跑的程式。**

---

## 0. 最重要的一條：風格不是你的事

儀表板是**給專案人員看**的，要求全站**風格一致、一目了然**。所以：

- **你（agent）只負責填「資料」，不負責「畫面」。** 你唯一要碰的是結構化的 `.ai/status.json`。
- **不要**自己產生 HTML、不要自訂顏色/版面/排版、不要在專案內另做一頁儀表板。
  視覺呈現一律由中央 `D:\專案管理\process\build_dashboard.py` 統一渲染（狀態色、警示燈、時間軸都是它算的）。
- 這樣不論哪個對話框、哪個專案來更新，**畫面永遠同一套**，不會五花八門。
- 你要做的，是讓「資料的寫法」也一致 —— 見第 3 節「寫法規範」，並照第 4 節「黃金範例」照抄格式。

---

## 1. 觸發時機

在每次「更新 `.ai` 的收工流程」的**最後一步**執行：
1. 先照原本習慣寫 `records/YYYY-MM/YYYY-MM-DD/01_daily_log.md`（及 bug_notes 等）。
2. **接著更新 `.ai/status.json`**（下述）。
3. **（必做）重生儀表板**——執行下列指令，把這次更新「合併回」`D:\專案管理`：
   ```
   python D:\專案管理\process\build_dashboard.py
   ```
   > 只更新 `status.json`、**不跑這步的話，儀表板不會變**（它是靜態 HTML，要重生才會反映新進度）。
   > 這步會：讀你的 `status.json` → 複製一份快照到 `D:\專案管理\data\` → 重生 `index.html` 與各案頁。
   > 若該專案未被納管（`D:\專案管理\projects.json` 白名單沒有它），先請使用者把它加進白名單。

## 2. 要維護的檔案：`.ai/status.json`

固定格式（若檔案不存在就新建，存在就就地更新）。**欄位名、結構不可改**——腳本靠它渲染：

```jsonc
{
  "project": "專案顯示名稱（一行，例：公母模脫膜檢查 / 公模四態分類）",
  "updated": "YYYY-MM-DD",           // 本次更新日期（驅動『幾天沒更新』警示燈）
  "state": "active",                  // active / paused / blocked / done 擇一
  "headline": "一句話講目前整體狀態（≤40字）",
  "locked": [                         // 鎖定項：里程碑/長期目標/阻塞，永遠顯示、不受 3 筆限制
    "已鎖定的成果或目標，一句一項",
    "⚠ 風險或阻塞項請用『⚠』開頭"
  ],
  "entries": [                        // 每日進度，最新在最前，最多保留 3 筆
    {
      "date": "YYYY-MM-DD",
      "today": "今日進度：今天實際做完/推進了什麼",
      "handoff": "明日交接：下一個窗口第一步該做什麼"
    }
  ]
}
```

## 3. 寫法規範（讓內容也一致，不只畫面一致）

同樣是給人看的，**每個人寫法不同就會亂**。一律遵守：

| 欄位 | 長度 | 寫法 | 好 vs 壞 |
|---|---|---|---|
| `project` | 一行 | 「主題 / 子題」；同一 repo 有多線就並列 | ✅`模號穴號 OCR + 公母模脫膜檢查`　❌`我的專案` |
| `headline` | **≤40 字** | 一句講**現在整體狀態**，含關鍵成果+最大阻塞 | ✅`公模分類97.3%已鎖定；GL光源仍未跨過`　❌`今天做了很多事` |
| `today` | **1～3 句** | **結果導向**：做完/推進了什麼，帶關鍵數字 | ✅`訓出v9並驗證零退步（M83 55%→99.9%）`　❌`跑了一些訓練實驗` |
| `handoff` | **1～3 句** | **動作導向**：下一步「做什麼＋對象」 | ✅`把v9推上部署樹並切換DEFAULT`　❌`繼續加油` |
| `locked` | 每項一句 | 一句一里程碑/目標/風險 | 見下 |

**通用語氣**：
- 用**陳述句、動詞開頭**；不用第一人稱（不寫「我」）、不用行銷語（不寫「完美」「大成功」）。
- **帶數字**（準確率、耗時、版本、張數），數字最能一目了然。
- 摘要**自當天的 `01_daily_log.md`**（`今日主題`＋`產出`→today；`待辦/未決`或 handoff「下一步」→handoff）。**不杜撰**，沒把握就照抄原文再精簡。

**`locked` 的特別規則（會影響渲染顏色）**：
- 一般里程碑/成果/目標 → 正常寫，渲染成**綠色里程碑卡**。
- 風險 / 阻塞 / 未解問題 → **開頭加『⚠』**（例：`⚠ GL 光源公模跨不過（F7 65%）`）。腳本偵測到 `⚠/阻塞/風險/未解` 會自動渲染成**紅色風險卡**。所以「想讓它變紅＝用⚠開頭」。

**`state` 用詞對照**（照這個判，不要自創）：

| state | 用在 | 渲染 |
|---|---|---|
| `active` | 正在推進 | 🟢 進行中 |
| `paused` | 主動暫停、轉去做別的 | 🟡 暫停 |
| `blocked` | 被外部卡住（缺資料/等回覆/等硬體） | 🔴 受阻 |
| `done` | 已結案交付 | ⚪ 已結案 |

## 4. 黃金範例（照這個抄格式）

這是 `Content_lens_OCR` 的實際 `status.json`，**當作參照物**：長度、語氣、數字密度、⚠用法都照它。

```json
{
  "project": "隱形眼鏡辨識 (Content_lens_OCR)：模號穴號 OCR + 公母模脫膜檢查",
  "updated": "2026-07-13",
  "state": "active",
  "headline": "公模四態分類 CHS 97.3% 已鎖定；GL 光源仍未跨過、母膜缺圖阻塞主檢查器。",
  "locked": [
    "CHS 光源公模四態分類 97.3% 已鎖定（_gong_validate_fast.py，兩段式定心，~110ms/張）",
    "模號穴號 v9/v9.2 全量重訓『零退步』驗證成立，但部署 DEFAULT 仍為 V6 未切換",
    "⚠ GL-IFV40W 光源公模跨不過（F7 65% / F7.9 22%）；母膜尚無有效資料"
  ],
  "entries": [
    {
      "date": "2026-07-13",
      "today": "評估 gongmu_handoff_v2 交接包路線 → 把散在 repo 根目錄的 52 個 _gong_*.py 與 _gong_defect 整併進新建的 公母模/（純增量、零覆蓋）。",
      "handoff": "決定 _mold_thumbs/(20M) 是否收進 公母模/；commit 前把 _gong_defect/{viz,preview} 加 .gitignore；模號線 DEFAULT 待切 V9.2。"
    }
  ]
}
```

> 注意每筆的字數、動詞開頭、括號補關鍵數字、風險項用 ⚠ —— 這就是要對齊的「風格」。

---

## 5. 更新規則（每次收工）

1. **新增一筆**：把今天的 `{date, today, handoff}` **插到 `entries` 最前面**。
   - 若今天已有同 `date` 的一筆 → **覆蓋**它，不要重複新增。
2. **只留最新 3 筆**：`entries` 超過 3 筆時，**刪掉最舊的**（原始細節仍在 `records/`，這裡只是摘要視窗）。
3. **鎖定項獨立**：`locked` 不受 3 筆限制，一直顯示。
   - 加入：已鎖定成果、長期目標、里程碑、未解重大阻塞（阻塞記得 ⚠ 開頭）。
   - 移除：該項失效/完成/被取代時，人工或依使用者指示移除。
4. **`updated` 一律填今天**；**`headline` 每次重寫**成當下最新狀態。
5. **只碰 `status.json`**，不動 `.ai` 其他既有結構（records / context / templates 照舊）。

---

## 6. 欄位如何呈現（懂了才知道怎麼寫）

| 你寫的欄位 | 出現在哪 | 效果 |
|---|---|---|
| `state` | 主控頁色帶＋狀態燈、內頁 Hero 邊色 | 決定綠/黃/紅/灰 |
| `headline` | 主控頁卡片、內頁 Hero | 一句抓住現況 → 要精準 |
| `updated` | 主控頁/內頁警示燈 | 今天/昨天(綠)→N天前(黃)→⚠N天未更新(紅) |
| `entries[0]` | **主控頁卡片只顯示最新這 1 筆**的 today/handoff | 最新一筆最重要，要寫好 |
| `entries`(全部) | 內頁時間軸（最新有「最新」標籤+綠脈衝點） | 最多 3 筆 |
| `locked` | 內頁「鎖定項」卡片區 | 綠=里程碑；⚠=紅色風險卡 |

## 7. 首次導入（該專案還沒有 `status.json` 時）

1. 讀該專案 `context/current_handoff.md`（若有）＋最近 1～3 天的 `01_daily_log.md`。
2. 依第 3、4 節格式生成初版：`entries` 回填最近最多 3 筆、`locked` 放已知里程碑/目標（阻塞加 ⚠）。
3. 之後改由第 5 節「收工流程」逐日維護。

---

## 8. 給人的一句話

> 收工前，除了寫 daily_log，**順手把 `.ai/status.json` 更新一筆**（照黃金範例的寫法）——
> 畫面交給中央腳本統一渲染，你只要把資料寫對、寫齊，首頁就會一目了然。
