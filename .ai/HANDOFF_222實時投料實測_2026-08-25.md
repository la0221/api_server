### 2.1 為什麼把 `TrustInput` 改成 `Skip`（使用者拍板）

原本「低信心不符 → 採信操作員 → 當良品放行」。使用者要求關掉，理由成立：

- 真混料時，**操作員填的工單當然還是原料號** → 採信操作員＝放掉最該攔的那片（fail-open）
- 實測 `read=M10/M5 conf=0.31/0.59` —— **穴號 `M5` 是不可能的值**，那不是「模型搖擺」而是**爛圖**，卻被當良品放行

改成 `Skip`：**不放行、也不吹**（低信心多半是取像問題，拿氣閥去補只會誤吹良品——這點是使用者特別強調的，**不要改成「一律攔截吹掉」**）。

> ★ **`ServerBudgetMs` 絕對不要改回 100**。原值 100ms 造成**連續 6 片良品被誤吹**：
> CRNN 實測延遲 88~380ms 正好卡在門檻上，降級/恢復每 2~3 秒來回跳，
> 落在降級瞬間的片子被本機舊雙head讀錯（**信心 0.99 卻讀成 M53**）→ 判混料 → 吹掉良品。
> 改 10000 後**零降級**（實測 107 次觸發）。
> 程式對此欄有 `Math.Clamp(20, 10_000)`，**填超過 10000 會被夾掉**，故直接填上限。
> **正解是程式判斷 loopback 時停用降級**（需求 1，未做）。

| 吹氣 | 收訊號 **2ms** 內 Air ON，吹 310ms 自動關；連續 NG 會**延長不中斷**（實測 555ms） |
| 降級修正後 | **107 次觸發、FALLBACK=0** |

### 光學調校（今天的主要瓶頸）

**決定性實驗**：同一張實機 strip 重送 CRNN 8 次 → `000171` **0/8**、`000172` **8/8**（信心一模一樣）
→ **CRNN 完全確定性，不是模型不穩**。
兩張圖像素比對：位移 `dx=0.04/dy=-0.15`（等於沒位移），只差 0.94% 雜訊
→ **排除圓心抖動、接縫**。
對失敗圖做變換再送：旋轉180°/上下翻/水平捲動 **都讀不到**，
**只有「對比增強 alpha=1.6 β=-40」→ 讀到 M49/15 conf=0.95** → **根因＝對比不足**。

曝光調整實測（strip 內容帶）：

| 曝光 | 中位數 | 飽和 | 對比(std) | 模號信心平均 |
|---|---|---|---|---|
| 1300µs（原值） | **255（完全飽和）** | 58.4% | 42.0 | 0.55~0.58 |
| 900µs | 118 | 31.7% | **72.7** | **0.86**（21 筆） |
| **1000µs（現值）** | 134 | 31.7% | 64.8 | **樣本不足（僅 2 筆 0.37/0.56）** |

→ **1000µs 的模號信心還沒統計夠，下一步就是多投幾片統計；若明顯低於 900µs 的 0.86 就退回 900**
（對比比亮度重要）。

## 6. 操作備忘（踩過的坑，會省下很多時間）

### 遠端操控 222（從 221）

- SSH 免密碼已設好：`ssh w222`（金鑰 `~/.ssh/id_ed25519_222`，無 passphrase）
- **從 SSH 啟動的行程會隨 session 結束被殺** → 服務要用
  `Invoke-CimMethod Win32_Process Create`（脫離 job object）
- **GUI 必須在 session 1**（使用者的實體螢幕），SSH 在 session 0 →
  用 `Register-ScheduledTask` + `New-ScheduledTaskPrincipal -LogonType Interactive`
- UI 自動化可行：`UIAutomationClient` 的 `InvokePattern.Invoke()`
  **不搶焦點、不動滑鼠**；登入框的 `PasswordBox` 意外地支援 `ValuePattern.SetValue`

### 編碼陷阱（踩很多次）

- **`.ps1` 傳到 222 必須存 UTF-8 with BOM**，否則 PowerShell 5.1 用 ANSI 讀 → 中文變亂碼、比對全失敗
- **`.bat` 內容不能有中文**：Big5 有些字第二位元組落在 ASCII 特殊字元上會把指令切碎；
  **路徑更不能有中文**——`D:\新增資料夾` 的「新」是 `A6 5C`，**第二位元組就是反斜線**，
  cmd 會從中間斷開 → 解法是 bat 放進 exe 目錄用 `%~dp0`，桌面只放捷徑
- **`cv2.imread` 讀不了中文路徑** → 用 `cv2.imdecode(np.fromfile(...))`
- **`scp` 的遠端中文路徑會失敗** → 先在遠端 `Copy-Item` 到 `%TEMP%` 再取
- PowerShell 5.1 `Get-Content` 對無 BOM 檔案預設 ANSI，驗 JSON 會誤判「壞掉」
  （.NET 8 讀 JSON 一律 UTF-8，其實沒壞）
- `pip install` 用 `Start-Process -RedirectStandardOutput` 會**死鎖**（緩衝塞爆），
  白等 50 分鐘 torch 一個位元組沒下載 → 改 `cmd /c "... > log 2>&1"` + `--progress-bar off`

### 診斷手法（今天靠這些定位問題）

- **同一張圖重送 N 次** → 分辨「模型不穩」vs「影像差異」（結果：CRNN 完全確定性）
- **像素級 diff + 相位相關求位移** → 排除圓心抖動
- **對失敗圖做變換再送**（旋轉/翻轉/捲動/對比）→ 單一變數定位根因
- strip 內容帶 `[290:350, :]` 的中位數/飽和率/標準差 → 量化曝光是否過曝
- 三邊對照：站端 `records\*.json`、父端 `/api/infer/recent`、吹氣服務自己的 `logs\*.log`
  —— 今天就是靠「父端讀 M49、站端送 M53」的矛盾抓到降級誤吹
