## 2. ★ 抓到一個會上線才爆的相容性問題

對方的判定是「**收到的字串含 `NG`（不分大小寫）就吹**」。
我方原本送的是相機版那套 JSON：

```json
{"type":"blow","channel":0,"reason":"MISMATCH","id":"T000123","expect":"M108/14","got":"M17/14",...}
```

**整串字沒有 `NG` 這兩個字。**

實測（用逐行複刻他們判定邏輯的 mock）：

```
收到："{"type":"blow","reason":"MISMATCH",...}"        → ✘ 不含 NG → 忽略（不吹）
收到："NG reason=MISMATCH id=... expect=M108/14 ..."   → >>> 吹氣 ON → 300ms → OFF
```

> **症狀會是：混料照樣判、兩邊 log 照樣寫、就是不吹，而且雙方都不報錯。**
> 這種東西不會在辦公室被發現，只會在現場「怎麼沒吹」時才浮出來。

⚠ 只有 `reason=NG` 那種會**碰巧**觸發（因為 JSON 裡剛好出現 NG 兩個字）——
更糟：混料不吹、不良品會吹，看起來「有時候會動」，更難查。

---

## 3. 改了什麼

| | 改前 | 改後 |
|---|---|---|
| Port | 5001 | **5000** |
| 格式 | JSON | **NgText**（`NG` 開頭 + 脈絡；`Format` 可切回 `Json`） |
| 連線 | 每次重連 | **長連線**（依對方建議；斷線自動重連並重試一次） |
| 編碼 | UTF-8 | **ASCII**（對方用 `Encoding.ASCII` 解；非 ASCII 先換成 `_`） |

送出的內容：

```
NG reason=MISMATCH id=T000123 expect=M108/14 got=M17/14 conf=0.97/0.96 ts=13:47:42.309
```

**刻意不送光禿禿的 `NG`** —— 對方會把收到的原始內容寫進自己的 log，
帶上脈絡等於兩邊 log 可以直接對帳（誰在幾點因為什麼吹了哪一片）。

設定畫面新增「送 JSON 格式」勾選，並附**紅字警告**（勾錯是無聲失敗）。

## 新發現 6 個

**⑴ 🔴 一張裁不到圓的圖，會讓後面 30 秒的好圖全部不送中央。**
鏈路：前處理找不到圓 → `sentBytes = rawBytes`（原始 **JPEG**）→ 但 client 固定宣告 `format=png`
→ 父端依約回 **415** → client 把任何非 2xx 當失敗 → VM 解讀成「中央掛了」→ **30 秒冷卻** → 全部本機接管。
實測（中央全程正常）：**送達中央 0 ／ 本機接管 7**，畫面警告「請檢查伺服器位址與連線」。
**這改寫了 8/17『本機接管 61%』的解釋** —— 那個數字可能不是「本機模型只有 61%」，
而是「一堆本來該送中央的圖被誤降級」。修好前，61% 不能拿來做決策。

**⑵ 🟠 父端主頁「每 5 秒自動更新」從來沒啟動過。**
`_timer.Start()` 只寫在 `OnAutoRefreshChanged` 裡，而 `_autoRefresh` 初值就是 `true`
→ 值從沒改變 → 那個 partial method 永遠不會被呼叫。
實測：不碰它 100 秒，畫面時鐘凍結、累計停在 8（API 真值 28）；手動按「重新檢查」才對。

**⑶ 🟠 `localhost` + 綁 `0.0.0.0` → 每條新連線白等 ~2.05 秒**（先試 `::1` 卡住才退回 IPv4）。
結果「測連接埠」「套用並測試連線」**回報錯誤的「埠關閉/不可達」** —— 比無聲失敗更糟，
它會把現場工程師送去查防火牆，而交接檔 §4① 正好要按這兩顆。
量到 5 次，3 次來自程式自己的 log（e2e 2254ms vs serverMs 194ms）。改綁 `[::]` 實測即解。

**⑷ 🟡** 吹氣設定「目前通道」與測試訊息不隨格式更新 → 勾了 JSON 仍顯示「NG 純文字」，§1 的防呆被抵消。
**⑸ 🟡** 父端視窗預設 1180×800 塞不進 1024×768（E10）。
**⑹ 🟡** `StationRow` 漏了 `ToString()`。

# 追記三：父子實時推論流程，設計 §11 六步一路做完

📄 設計＋實作紀錄：**`.ai/designs/2026-08-24_父子實時推論流程.md`**

照**已驗證的相機版**（現場在跑、手上所有模號穴號訓練圖都是它拍的）把觸發模型搬進來：

兩段式閘門（只 Hough 的便宜探測）→ 命中才前處理送父端 → **站端拿工單判定** → 三件套落地 → 混料/NG 吹氣。

新增 11 個檔案（`Services/Realtime/*`＋`LensProbe`＋VM/View）。入口：面板 → 模號穴號實時檢測（觸發式）。

## ★ 實作中抓到三個問題（都已修）

**⑴ 預算逾時直接取消 HTTP 請求 → 把父端 sidecar 弄壞。**
父端走 stdin/stdout 一問一答；請求被砍掉時 python 還在處理上一筆，而我方 finally 已把暫存圖刪了
→ 下一筆讀到已刪除的路徑 `[Errno 2] No such file`，**一次取消污染後面連續 15 筆**。
徵兆很明顯：中央比例隨預算變大反而遞減（100ms→63%、300ms→25%）。
**修法：預算到了只「停止等待」，不中止對方**（`Task.WhenAny`），讓它自己跑完、結果丟掉。
修後 36 次推論 0 失敗、0 暫存殘留。

**⑵ sidecar 暫存圖放 `%TEMP%` 被防毒短暫鎖住** → `[Errno 13]`，12 次失敗 1 次（8%）。
改放 `<程式目錄>\tmp\crnn\` + 檔案錯誤換檔名重試一次。

**⑶ 一次瞬斷就進 30 秒降級冷卻** → 與今早 Route A 那個「一件事連坐一整批」同一種坑。
改成連續 3 次才冷卻、成功即歸零；**逾時完全不進冷卻**。

另修：閘門比正式前處理還嚴（它自己會把裁切框夾進影像內），會把讀得到的片子誤判成擷取失誤
→ 加 `LensEdgeTolerance`（半徑 10%，可設定）；停止時「已記帳又被算成中斷」造成假性帳不平 → 加 `Counted` 旗標。

## ★★ 父端預算實測：100ms 太小

同一台、暖機後、真實影像，各 8 片：

| 預算 | 走中央 | 父端耗時 |
|---|---|---|
| **100ms**（原拍板） | **2/8　25%** | 101–107ms |
| 150ms | 5/8　63% | 108–115ms |
| **200ms** | **8/8　100%** | 102–190ms |
| 300ms | 8/8　100% | 100–188ms |

照 100ms 跑，**四分之三的片子會落到本機那顆較舊的雙 head**。建議 `ServerBudgetMs` 設 **200**。
⚠ 這是單站本機迴路的數字；跨機加網路、多站搶 GPU 都會更慢，現場要重測。

## 驗證：52 項全過，全部無視窗

單元 23（含**故意漏記帳要被抓出來**）＋ E2E 父端不可用 21 ＋ E2E 真父端 API 8。

# 追記五：ROI 框補齊（對齊相機版的完整功能）

我原本只在實時檢測頁「把框畫進點陣圖」—— 那只是相機版的一小塊，**而且做法本身也錯**
（1280×1024 的 PNG 編碼一次 10~30ms，每顯示一幀付一次；而且畫進圖裡就做不了拖曳框選）。

| | 相機版 | 我原本 |
|---|---|---|
| ROI 存法 | **影像比例 0~1**，與解析度無關 | appsettings 的**像素**，換相機/改解析度就錯位 |
| 畫法 | Canvas 疊層，**永遠畫出送 OCR 的範圍** | 畫進點陣圖再重編碼 |
| 拖曳重新框選 | ✅ 含即時座標、Esc 取消、太小放棄 | ❌ |
| 重設 / 存檔 | ✅ 存檔即生效 | ❌ 要改 appsettings 再重啟 |
| 主頁預覽 | ✅ 一直畫著 | ❌ 完全沒有 |

**現在**：`Services/RoiSettings.cs`（比例存 `configs/roi.json`，第一次執行自動從 appsettings 像素搬家）
＋ `Views/Controls/RoiPreview.xaml`（共用疊層控制項：顯示／拖曳框選／即時座標／Esc／<50px 放棄）。

- **實時檢測頁**：完整功能
- **主頁預覽**：唯讀顯示（誤觸就把整條產線的判定區改掉了，要改去實時檢測頁）
  → 這也了結 8/24 交接檔待辦 ④「ROI 疊在預覽上」
- 框選完 `Changed` → 管線 `RefreshRoi()` 立刻換算成當下幀尺寸 → **畫面畫的框＝實際判定的區**

**驗證 ROI 16 項，總計 80 項全過。** 重點兩條：
**解析度翻倍 ROI 跟著翻倍**（存比例的意義）、**已有 roi.json 就不被 appsettings 蓋掉**（檔案才是現場真相）。

**現場用法**：開實時檢測 → 看黃框 → 沒對準按「重新框選 ROI」拖一個 → 放開即存檔生效；拖壞按「重設」。
