## 一、逐項回覆「待確認事項」

| 你們問的 | 我方回覆 |
|---|---|
| **實際 NG 訊號的封包格式** | **ASCII 純文字、一行、`\n` 結尾**。格式：<br>`NG reason=<原因> id=<流水號> expect=<預期模號>/<預期穴號> got=<偵測模號>/<偵測穴號> conf=<信心>/<信心> ts=<時分秒.毫秒>`<br>**開頭固定是 `NG`**，所以你們現有的「含 NG 就吹」不必改。後面那串是給**你們的 log 對帳**用的，不需要解析。 |
| **是否需要回傳 ACK** | **不需要**。我方送出即忘；送不出去只記自己的 log，不會重試也不會影響辨識流程（吹氣是判定之後的後段動作，不能反過來拖累產線）。 |
| **連線方式：長連線 or 短連線** | **長連線**（依你們建議）。連線斷掉我方會自動重連並重試一次。可在設定改成短連線。 |
| **目標 IP / Port** | **沿用 5000**，不需調整。IP 由現場填（我方畫面上可設定）。 |

### 實際封包範例

```
NG reason=MISMATCH id=T000123 expect=M108/14 got=M17/14 conf=0.97/0.96 ts=13:47:42.309
```

- `reason`：`MISMATCH`（混料）／`NG`（不良品）／`TEST`（我方畫面上的測試按鈕）
- `id`：單片流水號，**同一片只會送一次**（我方已做去重）
- `expect` / `got`：工單預期值 vs 模型判定值 —— 出事時可直接比對是哪一片、錯成什麼
- 全部欄位保證 **ASCII**（非 ASCII 字元我方會先換成 `_`，避免你們 `Encoding.ASCII` 解出亂碼）

## 二、⚠ 我方發現的一個相容性問題（已修，但請知悉）

我方原本沿用另一套自製 IO 監聽程式的 **JSON 格式**：

```json
{"type":"blow","channel":0,"reason":"MISMATCH","id":"T000123","expect":"M108/14","got":"M17/14",...}
```

**這串字整串沒有 `NG` 這兩個字** → 依你們「含 NG 才吹」的判定會被當雜訊丟掉。
症狀會是：**混料照樣判、兩邊 log 照樣寫、就是不吹，而且雙方都不報錯。**

已實測確認（用你們 `Program.cs` 的判定邏輯逐行複刻）：

```
收到："{"type":"blow","reason":"MISMATCH",...}"   → ✘ 不含 NG → 忽略（不吹）
收到："NG reason=MISMATCH id=... expect=M108/14 got=M17/14 ..."  → >>> 吹氣 ON
```

我方已改為預設送 NG 純文字，並在設定畫面把這個選項標成紅字警告。
**若日後你們改用固定封包格式（header／長度／Modbus TCP），請告知，我方切換只是改一個設定值。**

## 三、⚠ 回饋給你們的兩點建議

### 1. 沒有研華卡時，服務會**完全不監聽**（不只是不能吹）

`Program.cs` 的順序是：

```csharp
OpenDeviceAndDiscoverDo();     // ← 卡不在就在這裡拋
...
listener.Start();              // ← 永遠走不到
```

所以在**沒有 IO 卡的機器上完全無法測試對接**（我方這次只能自己複刻你們的判定邏輯來驗）。

**建議**：把 TCP 監聽提前到 IO 初始化之前，或加一個 `--no-io` 模擬模式 ——
這樣對接雙方在辦公室就能先把協定跑通，到現場只剩接線要驗。

### 2. 連線進來但**送的東西不含 NG** 時，log 看不出「被忽略」

目前只會記 `[TCP] Received from ...: "..."`，不含 NG 就靜靜跳過。
現場排查「為什麼沒吹」時，會分不清是**沒收到**還是**收到但不認**。

**建議**：不含 NG 時多記一行，例如
`[TCP] Ignored (no "NG" token): "..."`。

## 四、我方這端怎麼設定（供你們了解全貌）

站端 App → **系統 → 吹氣觸發設定**：

| 項目 | 說明 |
|---|---|
| 啟用吹氣觸發 | 總開關。關閉時完全不送 |
| 混料／不良品 各自要不要吹 | 現場常常只吹混料 |
| **延遲（毫秒）** | 判定完成到送訊號之間等多久 —— **工件從拍照位走到吹嘴的時間**，用碼錶量出來填 |
| IO 主機位址／埠 | 你們那台的 IP／`5000` |
| 維持長連線 | 預設開 |
| **測試吹氣** | 不必等真的混料，直接送一發驗吹嘴與延遲 |

設定存 `configs/blow.json`，**存檔即生效不必重啟**。

## 五、現場對接建議順序

1. 你們那台起 `NgAirBlowService`，確認 log 有 `[TCP] Listening on port 5000`
2. 兩台互 ping 不算數 —— 用 `Test-NetConnection <你們IP> -Port 5000` 看 `TcpTestSucceeded`
   （防火牆常擋 ICMP，ping 不通不代表埠不通）
3. 我方畫面填好 IP → **按「測試吹氣」** → 你們 log 應出現
   `[TCP] Received ... "NG reason=TEST ..."` 且吹嘴動作
4. 用碼錶量工件從拍照位到吹嘴的時間 → 填進「延遲」→ 再按一次測試吹氣對時機
5. 最後才跑真實產線驗混料
