# NG 吹氣觸發服務 — 對接說明

## 概述

本機為 **TCP Server**,等待對方設備主動連線並傳送 NG 判定訊號。收到訊號後,本機會觸發吹氣 IO 動作 0.3 秒,之後自動關閉。

```
你的設備(NG 判定端)                本機(NgAirBlowService)
     │  1. 主動連線 TCP                    │
     ├─────────────────────────────────>  │  監聽 Port 5000
     │  2. 傳送含 "NG" 的字串               │
     ├─────────────────────────────────>  │  收到後觸發
     │                                     │  DO 吹氣 0.3 秒 → 自動關閉
```

## 連線資訊

| 項目 | 內容 |
|------|------|
| 通訊協定 | TCP(本機為 Server,對方為 Client) |
| IP | 本機實際 IP(請依現場網路環境提供,如 `192.168.x.x`) |
| Port | `5000` |
| 資料編碼 | ASCII 純文字字串 |

## 訊號格式

目前為**最簡單版本**,判斷邏輯是:只要收到的字串內容包含 `"NG"`(不分大小寫),就視為 NG 訊號並觸發吹氣。

範例(以下皆會觸發):
```
NG
NG\n
ng
Camera1_NG
```

> 目前尚未定義固定封包格式(header、長度欄位等)。如貴司設備已有固定的通訊協定(例如 Modbus TCP、特定長度的 binary 封包),請提供規格,我們可以再調整解析邏輯。

## 動作邏輯

- 收到 NG 訊號 → 立即觸發吹氣,吹氣持續 **0.3 秒**後自動關閉
- 若吹氣期間(0.3 秒關閉前)又收到下一個 NG 訊號 → **重新從 0.3 秒開始計時**(延長吹氣,不會被中途打斷)
- 本機同時可接受多個 client 連線,每個連線獨立處理收到的資料

## 連線注意事項

- 建議對方設備**維持長連線**(connect 一次後持續送訊號),而非每次都重新 connect/disconnect,可減少延遲
- 若採用短連線(每次送完就斷開),本機也能正常處理,但每次都要重新建立 TCP 連線,會有額外的連線時間開銷
- 若對方與本機不在同一網段,需確認防火牆已開放 Port `5000`(TCP inbound)

## 測試方式(不需對方設備即可自行測試)

可用以下 PowerShell 指令模擬送出 NG 訊號:

```powershell
$client = New-Object System.Net.Sockets.TcpClient
$client.Connect("目標IP", 5000)
$stream = $client.GetStream()
$bytes = [System.Text.Encoding]::ASCII.GetBytes("NG")
$stream.Write($bytes, 0, $bytes.Length)
$stream.Close()
$client.Close()
```

## Log 紀錄

本機每次收到連線、收到的原始內容、吹氣 ON/OFF 時間點,都會記錄在:

```
<程式所在資料夾>\logs\yyyy-MM-dd.log
```

若對接過程中發現訊號沒反應或吹氣時機不對,可提供該時間點附近的 log 內容協助排查。

## 待確認事項(請對方工程師協助確認)

- [ ] 實際 NG 訊號的封包格式(純字串 / 固定 header / Modbus TCP 等)
- [ ] 是否需要本機回傳 ACK 確認收到訊號
- [ ] 連線方式:長連線 or 短連線
- [ ] 目標 IP / Port 是否需要調整(目前預設 5000)
