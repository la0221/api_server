# `.report/` — 大進度（給老闆／甲方看的整體進度）

> 專案：AIVision
> 除了本說明外，這個資料夾**只放 `report.json` 一個檔**。不要在這裡建任何其他檔案。

## 這層是什麼

| | `.ai/`（細節） | `.report/`（本層，大進度） |
|---|---|---|
| 內容 | 每天做了什麼、明日交接 | 整體走到哪、覆蓋率、風險、下一步 |
| 給誰 | 接手的人、自己 | **老闆／甲方（會被單獨寄出去）** |
| 頻率 | 每天 | 有里程碑／要對外報告時 |
| 怎麼更新 | 打 `/進度` | 打 **`/大進度`** |

## 怎麼更新（agent 看這裡）

1. **首選：使用者打 `/大進度`**，該指令會處理好一切。
2. 若被直接要求「更新 .report」：**先讀規則正本**
   ```
   D:\專案管理\大進度更新指令.md
   ```
   （schema、5 種 block、寫法規範、黃金範例、對外檢查清單都在那份，**以它為準**）
3. 只就地更新 `report.json` → 然後跑：
   ```
   python D:\專案管理\process\build_dashboard.py
   ```

> ⛔ **不要**自己產 HTML／自訂版面（畫面由中央統一渲染）、**不要**把規則複製到這裡、
> **不要**產出「我以為要做的事」之類的說明檔代替執行。

## 三個必記的約束（細節見正本）

1. **會被外人看到** → 不得出現內部路徑、腳本檔名、repo/slug 代號、內部黑話、內部人名、未確認臆測。
2. **要自足** → 對方沒有前情：`subtitle` 交代這是什麼系統的報告；不寫「如前所述」；數字寫全（例「5 / 19（26%）」）。
3. **要誠實** → 未驗證就寫「尚未經大量取圖驗證」，不美化成「已完成」。

## 格式骨架（完整版見正本）

```jsonc
{
  "project": "對外看得懂的系統名",
  "subtitle": "XXX系統 — 專案進度評估",
  "updated": "YYYY-MM-DD",
  "kpis": [ { "value": "19", "label": "已收圖模號", "note": "全數已納入模型", "tone": "good" } ],
  "sections": [
    { "title": "一、總覽", "blocks": [ /* 只有 5 種 block */ ] }
  ]
}
// block 型別：funnel（漏斗）/ bar（進度條）/ table（表格）/ note（提示框）/ text（純文字）
// tone 四選一：good(綠=完成/達標) / warn(金=未完成/待辦) / bad(紅=失敗) / info(中性)
```

**表格要上色**（讀者靠顏色掃重點，全灰=沒重點）。儲存格三種寫法可混用：
```jsonc
"rows": [[
  { "text": "✔ 完成", "tone": "good" },          // 上色文字
  { "tags": ["M101","M17"], "tone": "good" },    // 彩色標籤藥丸
  "一般字串照常用"
]]
```

**黃金範例**（照這個抄）：`D:\模號檢驗\.report\report.json`

## 產出

跑完 build 會產兩份：
- `D:\專案管理\reports\<slug>.html` — 內部看板用
- `D:\專案管理\reports\<slug>_share.html` — **對外版，單檔可直接寄出**
