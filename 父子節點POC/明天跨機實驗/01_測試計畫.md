# 明天跨機實驗 — 測試計畫

> 目的：把「多站架構」從本機推到**兩台真實機器**，量到**真網路延遲**，據以**定拓撲**（每站一台 PC？還是少數 PC 集中收多站？）。
> 本機已先跑過全套 acceptance（8 支 bat 全 PASS）；本文是明天**現場**的作戰計畫。

---

## 0. 角色與名詞（先搞清楚，別搞混）

| 角色 | 是誰 | 跑什麼 | 說明 |
|---|---|---|---|
| **父機 = 接收端 = server** | 例如 A1000（或任一台接收機） | 父端 exe（收圖→回結果） | 監聽 `0.0.0.0:8770`，等子機連進來 |
| **子機 = 發送端 = edge** | 隨意一台電腦 | 子端 exe（送圖→收結果→量時間） | 主動連父機 IP:8770 |

**圖永遠是「子機 → 父機」單向送、父機回 JSON**。這就是我方定案的 push / Route A 方向。

---

## 1. 環境需求（缺一不可）

- **兩台實體機器**（★不能同一台打自己：127.0.0.1 走 Windows loopback，量到的是 ~1ms 軟體開銷，**不是真網路**）。
- **同一區網、能互通**；**有線優先**（要順便比 WiFi 就兩種各測一輪）。
- 父機：把整個 **`dist\` 資料夾**複製過去即可（A 類 exe **免安裝**）。
  - ★**父機若是 Linux**：改用 `dist\linux\`（`run_parent_stub.sh`，只需 python3、免編譯免 pip），詳見 `dist/linux/README_LINUX.md`。子機不變。
- 子機：同樣複製整個 **`dist\` 資料夾**。
  - 跑 A 類（`連線測試\2_子_壓測` / `連線測試\3_子_DEMO_一張一張`）：**免安裝**，圖用 dist 內建 `sample_images\`（已打包 30 張）。
  - 跑 B 類 Route A（`真實測試\2_子_RouteA真前處理送出_跨機`）：該機需 **Python 3.13（64 位元）**，且**先裝環境包** → 跑 `dist\環境配置\子\安裝_子_離線.bat`（或 `安裝_子_線上.bat`，裝 numpy+opencv、免 torch，見 `dist\環境配置\子\README_子.md`）。⚠ 別以為「Python 有就有 cv2」——乾淨機沒裝就會 ModuleNotFoundError。
- 父機知道自己 IP：開 cmd 打 `ipconfig` 看 **IPv4**（例 192.168.0.x）。

## 2. 測試項目（依序做，前 3 項是主菜）

| # | 項目 | 父機跑 | 子機跑 | 量什麼 | 預期 |
|---|---|---|---|---|---|
| **T1** | **純傳輸延遲**（主菜） | `連線測試\1_父_純傳輸測試_假推論` | `連線測試\2_子_壓測` 輸父 IP | `p50 − 54ms = 真網路來回` | 有線 ~0.5–3ms；WiFi 5–30ms+ |
| **T2** | **併發吞吐**（主菜） | 同上（不用重開） | 同 `連線測試\2_子_壓測`（看 conc 1/2/4 列） | 各併發的 `rps` | rps 隨併發上升＝傳輸沒卡住 |
| **T3** | **網路穩定度**（主菜） | 同上 | 同 `連線測試\2_子_壓測` | `err`、`p99`、`max` | err=0；p99 不應爆遠大於 p50 |
| T4 | **Route A 跨機**（選） | `連線測試\1_父_純傳輸測試_假推論`（★跨機父端只用這支；`本機預演_*` 綁 127.0.0.1、遠端連不進，不可當跨機父端） | `真實測試\2_子_RouteA真前處理送出_跨機` 輸父 IP | payload 縮減、溯源、e2e | payload 少 ~69%；溯源 30/30 |
| T5 | **真 GPU 推論**（選，需 lens-gpu） | `真實測試\1_父_真GPU推論_存收圖`（該機要有 lens-gpu） | `連線測試\3_子_DEMO_一張一張` 或 `連線測試\2_子_壓測` | 真讀值 + 真推論 ms | 讀值對；單張 ~90–120ms |
| T6 | **Demo 給人看**（選） | 任一父端 | `連線測試\3_子_DEMO_一張一張` 輸父 IP | 一張一張 + 狀態頁大字 | 觀眾看得懂 |

> **T5 提醒**：A1000 若沒裝 lens-gpu 環境，**跳過 T5**，用 `1_父`(假推論) 專心量網路即可（真 GPU 吞吐改用我方 3050/A1000 本機另量，別卡在這）。

## 3. 每項怎麼跑（現場動作）

### T1–T3（同一組，一次做完）
1. **父機**：①（首次）右鍵「以系統管理員身分」跑 `父_開防火牆8770` ②`ipconfig` 記 IPv4 ③雙擊 `連線測試\1_父_純傳輸測試_假推論`（看到 `listen 0.0.0.0:8770` + `engine ready`）。
2. **子機**：雙擊 `連線測試\2_子_壓測` → Parent IP 輸入父機 IP → 圖資料夾按 Enter（用內建 sample_images）。
3. 看子機那張表：`conc / rps / p50 / p90 / p99 / server-ms`。**把整張表抄進 02_驗證與記錄。**

### T4（Route A 跨機，選）
1. 父機：`連線測試\1_父_純傳輸測試_假推論`（★跨機只用這支，綁 0.0.0.0；`本機預演_*` 綁 127.0.0.1 遠端連不進、且 proc-ms 40 會破壞 −54ms 公式）。
2. 子機（**須先裝 `dist\環境配置\子`**）：`真實測試\2_子_RouteA真前處理送出_跨機` → **輸父機 IP（不可按 Enter／不可 127.0.0.1）**。
3. 看：payload 少幾 %、**server-ok 幾/幾（若 server-ok=0＝全部沒送達，程式會大聲警告）**、`_routeA_out_real\manifest.jsonl`。
   - 若要真讀值：父端須是 `真實測試\1_父_真GPU`（--engine ocr）；打到 stub 會回罐頭 M101/02，程式也會警告。

### T6（Demo）
1. 父機任一父端啟動；子機 `連線測試\3_子_DEMO_一張一張` 輸父 IP。
2. 大螢幕瀏覽器開 `http://父機IP:8770/` 看即時大字結果。

## 4. 數字回來要幹嘛（決策邏輯）

- **T1 傳輸很便宜（有線 <3ms）** → 網路**不是**瓶頸，瓶頸是**算力** → 拓撲可走「**少數 PC 集中收多站**」（省機器），把火力集中在 P-B GPU + P-C session 池解串行。
- **T1 傳輸偏高（WiFi/雜訊大 / >10ms 且抖）** → 傾向「**每站靠近 edge 各一台**」或改有線。
- **T2 rps 不隨併發上升** → 傳輸或父機單核卡住，需查（見 02 異常判讀）。

**一句話**：這場實驗就是要用**真數字**取代「猜」，決定明天多站怎麼佈。
