## A. 怎麼讀數字（關鍵公式）

子機那張表每欄意思：

| 欄 | 意思 |
|---|---|
| `conc` | 併發數（同時幾個在送） |
| `ok` / `err` | 成功 / 失敗筆數 |
| `rps` | 每秒完成幾張（吞吐） |
| `p50/p90/p99/max` | 端到端來回延遲（含 HTTP+父端耗時）的分位數（ms） |
| `server-ms(p50)` | 父端「純推論/處理」耗時（假推論=54ms） |

**核心公式**：
```
真網路來回(約) = p50(端到端)  −  server-ms(p50)
```
例：p50=56ms、server-ms=54ms → **真網路 ≈ 2ms**（有線區網典型）。

## E. 異常判讀（數字怪就查這）

| 症狀 | 可能原因 | 怎麼辦（詳見 03 故障排除） |
|---|---|---|
| 子機全 `err`、連不上 | 防火牆沒放行 / IP 打錯 / 父端沒開 | 父機跑 `父_開防火牆8770`；核對 IPv4；確認父端視窗有 `listen` |
| `真網路` 算出來 ≈ 1ms 好到不真實 | 其實在打自己（loopback） | 確認子機輸的是**父機**IP、不是 127.0.0.1/自己 IP |
| `rps` 不隨併發上升 | 父機單核卡 / 網路頻寬滿 / Nagle | 記錄下來；多站真正瓶頸本就是算力，傳輸層 rps 平不一定是壞事，交叉看 server-ms |
| `p99/max` 暴衝、抖動大 | WiFi / 網路干擾 / 省電模式 | 換有線；子機關省電；重測 |
| Route A `server-ok < 送出` | 部分逾時 / 父端忙 | 看父端 console 有無錯；降低 --n 重測 |
| 真 GPU 讀值全一樣或亂 | engine 沒真的載成 ocr | 看父端啟動 log 是否 `engine=ocr`；該機是否真有 lens-gpu+模型 |
